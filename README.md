# FlowStudio

安卓上的移动端音乐工作站。自写的 C++17 实时音频引擎 + 全自绘 Kotlin 界面，零第三方依赖。

APK 约 1 MB（含原生引擎）。装到 arm64 手机上直接能编曲。

## 怎么跑

```bash
./tools/build_native.sh   # 交叉编译 C++ 引擎 -> libflowengine.so
./tools/build_apk.sh      # Kotlin -> dex -> aapt2 -> zipalign -> apksigner
adb install build/FlowStudio-1.0.0.apk
```

或者推到 GitHub，Actions 会自动出包（见 `.github/workflows/build.yml`）。

## 1.29 更新

### 音乐空间：三种新乐器 + 五种新效果器

原来只有六种音色，要写吉他分解、弦乐铺底或管风琴只能拿 Synth 硬凑；
效果器十种里缺"能让声音动起来"的那一类。这一版全部补齐，算法都用公开经典实现：

**新乐器**（ordinal 与 C++ 侧严格对齐）

| 乐器 | 算法 | 来源 |
|---|---|---|
| 拨弦 PLUCK | Karplus-Strong 数字波导 | Karplus & Strong, 1983 —— 物理建模的起点，至今仍是拨弦最划算的做法 |
| 弦乐 STRINGS | 三路失谐锯齿合奏 + 颤音 | 弦乐组"厚"的经典做法：微失谐 + 相位错开 |
| 风琴 ORGAN | 加法合成，9 根拉杆 | Hammond 拉杆风琴的谐波配比（0.5/1.5/1/2/3/4/5/6/8 倍） |

拨弦有两处踩过的坑写在代码注释里：**读与写必须落在同一个格子**（否则延迟退化成 1 个样本，
能量全跑到高频去），以及**激励要用棕噪声而不是白噪声**（白噪声让每个泛音一样响，
听起来像弹棉花，还会盖住基频）。另外加了分数延迟补偿，音准误差从几十音分降到 1 音分内。

**新效果器**

| 效果器 | 做法 |
|---|---|
| 电颤 TREMOLO | 正弦/方波/锯齿 LFO 的幅度调制 |
| 自动声像 AUTOPAN | 同 LFO，作用在左右两声道且相位相反，等功率声像 |
| 饱和 SATURATOR | tanh + 非对称项（产生偶次谐波，磁带味；纯 tanh 只有奇次，听着偏硬） |
| 噪声门 GATE | 侧链包络跟随 + 阈值开关 + 起音/释放平滑 |
| 立体声宽度 WIDTH | M/S 处理 + Haas 式伪侧信号（见下）+ 低频保持 |

宽度效果有个非显然的点：**纯 M/S 对单声道素材完全无效**（侧信号本来就是 0，
实测侧信号 0.0454 → 0.0454 一点没变）。所以这里先用两条不同延迟（4ms / 9ms）
的副本造出伪侧信号，再与真实侧信号叠加 —— 单声道素材也能加宽。

引擎自测从 62 项扩到 **80 项**，新增覆盖：三种乐器的基频正确性、五种效果器
"输出确实被改变"、电颤的峰值因数升高、宽度的侧信号增强、饱和的二次谐波增加。

### 顶部摆件

导航栏中段在宽屏上是纯色。这一版放了三个不接收触摸的小装置（`ui/OrnamentBar.kt`）：

1. **立体声电平**：两根细柱跟主输出峰值起伏，绿→黄→红分档，带峰值保持线。
   这是唯一"有用"的一个 —— 扫一眼就知道有没有声音。
2. **磁带卷盘**：播放时按约 3 秒一圈转，停止时停住。
3. **唱针臂**：播放时落到唱片上，停止时收回，角度做平滑过渡。

三者都是 Canvas 直接绘制，无图片资源、无动画框架。**静止时不请求下一帧** ——
这是实时音频软件，装饰动画不能跟音频线程抢 CPU。

### 插件：音频内容识别

新工具 `flowstudio_analyze_audio`：判断一段音频是人声、钢琴、吉他、贝斯、鼓、
弦乐铺底、管乐、合成器还是音效，并给出"放哪条轨、用什么乐器、怎么处理"。

不是黑盒模型，全部特征可解释：

- **解码**：ffmpeg → 单声道 44.1kHz（用 44.1k 不是 22.05k：高次谐波在 22.05k 下会折返，
  伪造出并不存在的基频 —— 实测一段 f0=180Hz 被读成 325Hz）
- **频谱**：自写 radix-2 FFT，提质心、滚降、平坦度、低/中/高频带比、
  1/3 倍频程频段能量
- **音高**：NSDF（McLeod & Wyvill，YIN 的前身）+ 分数延迟 + 倍频校正，
  9 个音高（82-880Hz）实测误差全部 < 1 音分
- **判别用的三个关键量**（都是踩坑后找到的）：
  - `midCoverage` 中频覆盖度：人声的共振峰是**连续一片**，锯齿波只有孤立的谐波峰
  - `midPeakiness` 中频尖峭度：谐波列（峰值/中位数大）vs 连续型频谱
  - `envDynamics` 包络动态：打击类方差大，持续类方差小
- **规则分类**：每条规则给 0..1 分，取最高；含反证项（"谐波性极强说明是乐音不是鼓"、
  "低频占比极高说明是贝斯不是弦乐"、"谐波性接近 1 说明是振荡器不是真拨弦"）
- **置信度**是"领先优势"，低于 0.15 明确说"不确定"并列出候选

验证：程序生成的五类标准素材（钢琴/贝斯/鼓/弦乐/人声）**5/5 全对**；
真实人声素材判为人声（置信度 0.50）。

## 1.28 更新

- **修中文请求体死锁（这一版最重要的一条）**：桥接原来用
  `BufferedReader` + `CharArray(contentLength)` 读 body ——
  Content-Length 是字节数，CharArray 装的是字符数。ASCII 请求体
  1 字节 = 1 字符，看不出问题；body 里一旦有中文（工程名、轨道名、
  投递文件名都是中文），3 字节才凑 1 个字符，`read()` 永远填不满
  `contentLength` 个字符，循环一直等到 **socket 读超时（20 秒）** 才返回
  截断的内容。表现就是：
  - 「推送超时，其实已经落库」—— 差一点重试把结果冲掉
  - 「音频导入 socket hang up」—— 被误判成体积墙，白做降采样
  - 「中文工程名打不开」—— `POST /projects/open` 挂 20 秒回空
  现在整个请求按字节处理：请求行/头部读到 `\n` 为止，body 精确读
  `contentLength` 个字节后一次性 UTF-8 解码。
- **新增删轨接口**：`DELETE /tracks/{i}` 与 batch 的 `tracks.delete`。
  以前桥接只能建轨不能删轨，导入失败留下的半截空轨没有任何出路，
  AI 只能把它改名成「空轨·可删」并静音，等用户去 App 里长按删 ——
  等于把自己造成的垃圾留给人收拾。删除时会一并清掉这条轨的音符、
  片段与自动化，并把大于该下标的一切整体前移。
- **投递目录改为可诊断**：`GET /inbox` 现在返回 `exists` / `canRead` /
  `canWrite` / `mediaPermissionGranted` 和一段人话说明，不再只是
  `pending: []`。过去这三种完全不同的故障（目录不存在、没有读权限、
  文件真被吃掉了）都表现为一个空数组，无从判断。
- **运行时申请 `READ_MEDIA_AUDIO`**：这才是「inbox 名存实亡」的真因 ——
  权限声明在清单里但从未在运行时申请，`granted=false`，App 连别人放进
  `Music/FlowStudio/inbox/` 的音频文件都列不出来，FileObserver 本身
  没问题。新增 `POST /inbox/rescan` 立刻补扫一次。
- `drainInbox` 区分「目录不存在」与「没权限」，把原因写进日志。

插件 1.4.0 同步：

- **修 `index.js` 残留 `import { readToken }`** —— 这个导出在 1.27 删掉了，

## 1.26 更新

- **修令牌镜像静默失败（401 的根因）**：令牌的镜像同步原来整体包在一个
  `runCatching` 里，任何一步抛异常都静默跳过 —— 表现就是"桥接在跑、
  Music/FlowStudio 下镜像全没了、插件永远 401"，日志里一行线索都没有。
  现在镜像拆成独立 `syncMirrors()`，四个目标各自 try-catch，
  失败原因逐条记进 `mirrorStatus`，`/status/health` 直接可读
  （新增 `tokenMirrors` 检查项）。
- **镜像目标加 Download 兜底**：`Download/.flowstudio_token`（点号开头不进媒体扫描）。
  实测 1.25 在这台设备上 Music 镜像没写出来，Download 往往仍可写。
- **onResume 重同步**：有些系统共享存储的挂载/授权晚于 Application onCreate，
  那时写镜像会失败。回到前台时存储一定就绪，补一次同步（幂等，几毫秒）。
  App 只要被打开过一次，镜像就是新的。
- 令牌本体保持稳定：只在私有文件不存在时生成，覆盖安装/重启都复用，
  不再出现"每次启动换令牌把插件踢下线"。
- 插件：令牌路径清单加上 Download 兜底与 bridge.json（能同时解析出端口）；
  bridge.json 里的端口参与 discover 探测（App 换过端口也能救回）。

## 1.24 更新

- **导音频支持 mp3 等压缩格式**：以前 AudioStore 只认 PCM WAV，
  导 mp3 会直接报"无法解码"。现在先试 WAV（最快路径），失败自动走
  MediaExtractor + MediaCodec —— mp3 / m4a / aac / flac / ogg 全支持，
  全是平台自带能力，不引第三方库。
  解码器输出 16-bit 整型与 float 两种 PCM 编码都处理了：只处理 16-bit
  的话，某些设备的解码器输出 float，表现就是静音。
  采样率保持源文件不动：引擎本来就会按 sampleRate 插值，解码端重采样
  只损失质量。上限 10 分钟 / 约 92 MB float，防手滑把整张专辑导进来。
- **免拉起传输（投递目录）**：新增 `/sdcard/Music/FlowStudio/inbox/`。
  把音频丢进去，App 里的 FileObserver（监听 CLOSE_WRITE，避免读到半个文件）
  立即导入成音频片段并删掉投递文件；App 没在运行时投的，下次启动扫描补导。
  桥接新增 GET/DELETE `/inbox` 两个端点，capabilities 声明 `audio.inbox`、`audio.mp3`。
- 插件新增 `flowstudio_drop_audio`：原样投递（mp3 就投 mp3，不用先转 WAV——
  这免掉了容器到手机 48MB WAV 的传输）；`flowstudio_fetch_music` 加 `drop: true`
  一步下载+投递。投递确认用素材数量对比而不是"文件消失"（文件消失也可能是清理）。

## 1.22.1 更新

- **修闪退**：`ArrayIndexOutOfBoundsException: length=361; index=361 @
  PlaylistView.drawNoteEnvelope`。根因是包络缓存 key 写成了 `clip.id * 31 xor cols`，
  把片段 id 和像素列数混进同一个数值空间 —— 片段 1 宽 97 列与片段 2 宽 64 列会算出
  同一个 key（126），拿到的是别的长度的数组，按当前列数循环就写越界。
  现在改成带长度的复合 key，并在绘制时再按数组实际长度兜一层。
  同样的输入空间下，旧写法的碰撞组合超过 10 万组，新写法零碰撞。
- 缓存 key 里加入了起点、长度、素材偏移：拖动或裁剪片段后包络会重算，
  不再停在旧位置。
- 缩放后整批清缓存的条件从 `bw.toInt()` 改成直接比较原始浮点值，
  避免两个接近的缩放比被截断成同一个整数而漏清。
- **状态面板不再误报**：音频流是**按需启动**的，没按播放时本来就不开流。
  以前「audioStream / render / signal」三项会同时标 ✗，看着像坏了。
  现在分成待机与失败两态，待机时标 ✓ 并写明「按需启动，按播放才开流」；
  只有「在播却没流」才真的报错。
- **播放失败不再假装成功**：`play()` 以前无条件 `play()` 并点亮播放键，
  即使 `startAudio()` 失败也照样走位置、照样没声音。现在返回布尔值，
  界面在流起不来时保持停止态并明确提示原因。
- 桥接 `/transport/play` 区分两种失败：主线程调度不上回 503，
  调度上了但流起不来回 200 + `warning`，避免插件重试一个重试也解决不了的错误。
- CI 增加静态检查：禁止把列数 `xor` 进缓存 key，实测能抓住回退。

## 1.22 更新

- **播放列表改成真·音频时间线**：音频不再是"一条全局伴奏轨"，而是可以摆在任意轨道上的
  音频片段。一条轨道上能放任意多段，可重叠、可裁剪、可拖到别的轨道 —— 这是 FL 的核心语义。
- 音频片段走所属轨道的完整混音链：推子、声像、四个插入效果、发送量。以前伴奏是绕过轨道
  混音直接进母带的，怎么调推子都不影响它。
- 素材与布局分离：波形只在导入时跨一次 JNI，之后拖动片段只传六个整型/浮点数组。
  一首三分半的歌约 38 MB float，每次拖动都重传会让界面直接卡死。
- 引擎新增 `setAudioBuffer` / `setAudioClipsById` / `clearAudioBuffers`：素材按 id 进池，
  片段按 id 引用。快照仍然是不可变 + `shared_ptr` 原子交换，音频线程不加锁。
- 片段支持左缘裁剪：拖左缘时起点、长度、素材偏移三者联动，露出来的那段音频保持不动。

  渲染循环，实测即刻归零。
- 修同一个原因导致的静音漏音：`hasAudio` 判断加上了 `audible` 条件。
- 新增引擎回归测试 12 项：音频片段出声、轨道静音生效、裁剪有效、清除彻底、反复替换不崩。

- 标尺数字自动跳格：小节太密时隔几个标一个，不再糊成一片。

## 架构

引擎和界面彻底分离，这是必须的：音频线程一次 GC 停顿就是一声爆音。

```
engine/                      纯 C++17，不依赖 Android，桌面上能直接跑单测
  include/flow/dsp.h         PolyBLEP 振荡器 / TPT 状态变量滤波器 / 双二阶 EQ / 分数延迟线
  include/flow/voice.h       发声单元（六种乐器）
  include/flow/effect.h      10 类插入效果
  include/flow/engine.h      调度、混音总线、母带、离线渲染
  src/voice.cpp              合成内核
  src/effect.cpp             效果器实现
  src/engine.cpp             传输 / 自动化 / 总线
  src/audio_android.cpp      AAudio 后端（低延迟路径，回调零分配）
  src/audio_null.cpp         宿主占位后端
  test/host_test.cpp         桌面自测，验证出声/音高/爆音/NaN/声像/导出长度

app/src/main/java/com/volt/flowstudio/
  audio/NativeEngine.kt      JNI 门面
  model/                     工程 / 轨道 / 样式 / 音符 / 效果 / 自动化
  session/StudioSession.kt   工程状态 -> 引擎调用，存盘读盘，导出 WAV
  ui/                        全部自绘：步进器、钢琴卷帘、播放列表、混音台、自动化、键盘
  MainActivity.kt            五个页签的主界面
```

## 功能

**编排**
- 步进器：16 分网格，拖动刷格子
- 钢琴卷帘：画、拖、拉长、改力度、量化、框选删除
- 播放列表：片段拖动、跨轨移动、拉长、循环区间
- 样式（Pattern）制，跟 FL 一样解耦轨道与样式

**音源**（全部实时合成，不含采样文件）
- 3 振荡器减法合成器（PolyBLEP 抗混叠）
- 减法贝斯
- 鼓组：8 类打击，底鼓带音高下滑
- FM 钟琴 / FM 电钢（带立体声颤音）
- 采样器（WAV 导入）

**效果**（每轨 4 个插入槽 + 2 条发送总线）
滤波、节拍同步延迟、Freeverb 混响、合唱、失真、压缩、6 段均衡、降位、移相

**混音**
- 每轨：推子、等功率声像、静音、独奏、电平表
- 母带：音量、前馈限幅、软削波、增益
- 自动化：包络曲线，编辑所见即所得

**其它**
- 后台播放（前台服务）
- 导出 16-bit 立体声 WAV，走系统分享
- 工程存档 JSON，自动保存

## 已知边界

- 只打了 `arm64-v8a`。要给 x86_64 模拟器跑，改 `build.gradle.kts` 的 `abiFilters`。
- 采样器只解 8/16/24/32-bit PCM 与 32-bit float 的 WAV。
- 自动化曲线是线性插值，不是贝塞尔。
- 录音（麦克风输入）留了权限和接口，尚未接线。
